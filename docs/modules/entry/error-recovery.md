# 异常恢复授权与退出边界

## 读取与来源

`module/config/recovery.py` 只读实例 JSON 的最新快照，不调用完整配置的 `load/bind`，不保存配置，不受业务代码临时 `override(Error_HandleError=True)` 绕过。配置损坏时禁止异常恢复。设备重试、平台内部失败兜底、调度器及监护共用 `check_error_recovery()`；其 `RecoveryStopped(SystemExit)` 不被业务层的 `except Exception` 吞掉。

正常关卡结束、心情等待、能力探测等已知流程继续使用原有结束或排期。换船、困难换船、SP 和战败处理在故障恢复或故障排期前同样核对总开关。SP 无法进入的人工异常不再假定为今日已完成；正常确认完成后的次日排期保持原行为。总开关关闭不是立即停止健康任务；一旦发生需要恢复的错误，保存最近已有截图和日志后，以错误码退出该实例 worker。不得重新截图、撤退、重连、启动游戏或排队故障任务。关闭异常处理时不等待外部推送；启用状态下需要人工介入仍保留错误通知。停止时跳过 LLM 分析和旧日志归档清理，避免延迟退出。错误现场副本仍遵守 `Error.SaveError`；普通日志和游戏画面保留。后台线程必须结束整个 worker，不能仅在该线程抛 `SystemExit`。当前实现只退出当前进程，不操作 WebUI、其他 worker 或模拟器进程。

## 恢复矩阵

| 来源 | 条件与行为 |
| --- | --- |
| 游戏退出、客户端 bug、未知页面、自动搜索设置失败 | 总开关允许且非严格敏感任务时，安排游戏 Restart；未知页面先检查维护状态 |
| 游戏卡死、连续点击 | 先允许游戏 Restart；只有 `GameStuckRestart` 开启且连续错误达到 `GameStuckThreshold`，才重启模拟器 |
| ADB/设备离线 | 查询前台应用的连接故障原样抛出，不冒充游戏退出；可有限重连和安排游戏恢复；只有 `AdbOfflineRestart` 开启且连续离线达到 `AdbOfflineThreshold`，才重启模拟器 |
| 人工接管、ScriptError、未分类脚本异常 | 保存现场并退出，不能猜测重启可修复 |
| 游戏重启中的启停超时 | 按 GameStuckError 处理，不伪装成设备离线；配置的启动次数与观察时间耗尽后请求人工处理 |
| 监护任务超时 | 每次检查总开关、子开关和分钟阈值；总异常处理、敏感保护、卡死重启开关与次数阈值均允许后才可中断模拟器，否则退出 worker 保留游戏现场；成功中断后下一检查周期仍是同一调用则停机，不反复杀模拟器 |
| 独立定时模拟器重启 | 只受模拟器管理自身开关和间隔控制；强制中断避让敏感任务，保留主动来源，使后续断连不误走离线开关 |
| 手动重启、主动任务、正常等待后的启动 | MCP 手动重启直接使用无连接 Platform；EmulatorManager 不先初始化游戏。 总异常开关不阻止第一次正常启停；操作失败后的恢复和重试仍需重新授权 |

`_try_restart_emulator(reason=...)` 在动作边界再次校验来源，每次仅启停一次，明确的 False 不能记为成功。深度重启和平台启动等待阶梯累计实际模拟器恢复失败次数，不能用设备离线检测次数代替。

## 动态配置与预算

- 已排队的故障 Restart 保留原故障来源，在等待服务器、选择任务或初始化设备之前重新检查；排队期间关闭总开关将停机，正常每日 Restart 不受此限制。
- 两个模拟器升级阈值都是连续故障**次数**，不是秒。普通业务成功后清零，Restart 成功不冒充故障任务已恢复。
- `Error.TaskRestartLimit` 仍按业务任务累计恢复轮次，达到后延至服务器下一次零点；0 明确表示不限次数。客户端启动自身耗尽配置尝试次数与观察时间后直接停机，不再排队重复一整轮。Restart 其他阶段的连续恢复失败由运行参数 `Reboot.Tries` 限制，达到后停止；尚未选出任务的初始化恢复也有相同预算。
- 上限改为 0 时，在任务选择前解除本进程的旧冷却。只对仍启用且持久化时间恰好等于本进程故障截止时间的任务恢复到当前时间，保留手工排期、禁用状态和其他任务设置。比较与写入使用配置事务锁。
- 设置观察复用一个轻量监护线程，即使监护和日报都关闭也只观察配置；开启后无需等当前长任务结束。日报仅在启用后创建服务与独立线程，关闭后退出，重新启用可重建；创建过程互斥。
- 恢复期间给设备添加临时上下文，每次截图、应用启停都重新校验授权，离开恢复范围后移除；不污染普通主动启停。主动启动首次失败后，后续重试和观察同样进入此上下文，观察每轮重新授权。设置观察也会停止已被撤销授权的恢复，避免阻塞 I/O 让主线程继续挂起。配置修改在下一次相应检查点生效。已经发出的系统启停命令不能撤销；不能把该事实当作允许下一轮恢复的理由。
- 独立 Device 的自动启动有连接尝试上限；离线阈值大于该预算时，达到上限仍抛出原始离线错误，不得越过未成功的连接继续初始化。

## 验证

主要离线测试：`tests.test_recovery_policy`、`tests.test_scheduler_recovery`、`tests.test_device_recovery`、`tests.test_device_backend_retry`、`tests.test_emulator_restart_mutex`、`tests.test_scheduler_live_loop`。进程验证只创建隔离测试 worker 和哨兵进程，不连接真实设备、不发送外部推送。设备平台操作与游戏登录实测必须按用户指定实例执行。
